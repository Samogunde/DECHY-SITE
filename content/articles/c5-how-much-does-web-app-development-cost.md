## Web app or website?

A website mostly shows information. A web app does work. As soon as people log in, enter data, book, pay, or see information that belongs only to them, you are building a web app. The difference matters for price, because every one of those actions needs screens, rules, storage, security, and testing.

Many businesses need both. A marketing website explains what you do and brings in leads. A web app behind a login is where customers or staff get things done. Pricing them separately keeps each quote clear.

## What moves the price of a web app

Five things account for most of the difference between a $5,000 tool and a $100,000 product.

The first is the number of user roles. An app used by one internal team is simpler than one used by staff, managers, customers, and partners, each seeing different screens and data.

The second is integrations. An integration connects your app to a tool you already use, such as accounting, a customer relationship management (CRM) system, or a payment provider. Each one is usually built through an application programming interface (API), the defined way one system shares data with another. Each connection adds design, building, and testing.

The third is real-time behavior. Live dashboards, chat, and instant notifications need extra infrastructure compared with pages that update when someone refreshes.

The fourth is data. Moving records from spreadsheets or an older system means cleaning, mapping, and checking every field.

The fifth is security and compliance. Apps that hold health, payment, or personal data need stronger controls and audit logs.

- User roles and permissions
- Integrations with your existing tools
- Real-time features such as live updates and chat
- Data migration from old systems
- Security and compliance requirements

## What is included in the price

Every web app quote we send covers the whole job. Discovery comes first: a workshop with the people who will use the app, and a written scope that lists what the first release does and does not include. Design follows, with a clickable prototype your team tries before anything is built.

The build happens in weekly rounds, each ending in a working version you can log into. Testing runs throughout. Launch covers hosting setup, data migration, training, and documentation, and you own the code when we finish.

- Discovery workshop and written scope
- Clickable prototype and screen designs
- The front end, back end, and database
- Integrations, testing, and launch
- Documentation and handover

## A typical timeline

A simple web app usually takes one to three weeks. The first days cover scope and design, the middle is the build, and the last days are testing and launch.

An advanced web app takes three to six weeks, with a review at the end of every week. A portal takes six to eight weeks. A subscription product takes two to three months, often split into a first release for early customers and a second release that adds billing tiers, team accounts, and reporting.

## How to keep the cost down

Start with the smallest version that solves the main problem. If customers mostly need to book and pay, launch that first and add reporting, loyalty, and extra roles later.

Use proven building blocks. Sign-in, payments, file storage, and email are solved problems, and reliable services handle them well. Building your own would cost more and add risk.

Connect, do not replace. If your accounting package works, link the web app to it rather than rebuilding invoicing inside the app.

Have your rules written down. Apps get expensive when business rules are discovered halfway through the build. A one-page description of how your process works today saves days of rework.

## A worked example

Picture a training company that runs courses in several cities. Today, bookings arrive by email, places are tracked in a spreadsheet, and invoices are created by hand. Staff spend hours each week answering the same questions about availability.

The first release is an advanced web app. Learners see upcoming courses, book a place, and pay by card. Staff see bookings in one dashboard and can move people between dates. Paid bookings flow into the accounting package automatically. That release falls in the $20,000 to $35,000 range and launches in about five weeks.

A second release adds a learner area with certificates and course materials, and a report showing revenue by course. It is quoted separately once the first release is in use, so the company pays for each step when it is ready.

## How to compare web app quotes

Ask each supplier for a written list of screens, roles, and integrations. Check that design, testing, data migration, and launch are included. Ask which parts are built from proven services and which are custom. Confirm that you will own the code, the database, and the hosting accounts. Finally, ask what care after launch costs, because a low build price with no support plan rarely stays low.

## Common questions

### How much does a simple web app cost?

A simple web app with one audience and a handful of screens usually costs {{fact:price.web-development-web-app}} and takes one to three weeks.

### Is a web app cheaper than a mobile app?

Usually, yes. A web app is built once and runs in every browser, while a mobile app needs store releases and testing on many devices. Many businesses start with a web app and add a mobile app once usage proves the need.

### How much does a SaaS product cost to build?

A subscription product with plans, billing, onboarding, and an admin console usually costs {{fact:price.software-development-saas-product}} and takes two to three months. A smaller first version for early customers can cost much less.

### What does a web app cost to run?

Hosting for most business web apps is modest. Plan for a care plan of {{fact:price.care-growth}} for apps in daily use, which covers updates, monitoring, and a set number of improvement hours.

### Can you work with a design we already have?

Yes. If your design is complete, the quote covers the build only, and the price drops accordingly.

### Do you charge extra for changes during the build?

Small swaps of similar effort are usually absorbed. Larger changes are described in writing with their cost before any work starts, so you decide whether they are worth it.
